# Деплой

Бот працює через long polling, тому йому не потрібні ні відкриті порти, ні
домен, ні реверс-проксі. Мінімальна конфігурація — будь-який VPS із Docker
(2 vCPU / 2 GB RAM більш ніж достатньо, сам контейнер обмежений 256 МБ).

## Встановлення

```bash
mkdir -p /opt/santa-bot && cd /opt/santa-bot
git clone https://github.com/diakirov/santa-teams-bot.git .

cp .env.example .env
nano .env            # BOT_TOKEN, ADMIN_ID, (опційно) HEALTHCHECK_URL
chmod 600 .env

# контейнер працює під непривілейованим uid 1000, тож директорія з базою
# має належати йому — інакше SQLite не відкриє файл
mkdir -p data && chown -R 1000:1000 data

docker compose up -d --build
docker compose logs -f --tail 50   # має зʼявитись «Стартую як @…»
```

Оновлення:

```bash
cd /opt/santa-bot && git pull && docker compose up -d --build
```

## Якщо на сервері вже є інші сервіси

Стек навмисно самодостатній, щоб не заважати сусідам:

- **окрема директорія й окремий compose-проєкт** — імʼя проєкту Docker бере з
  назви директорії, тому мережі не перетинаються. Не додавайте сервіс у чужий
  `docker-compose.yml`: тоді `docker compose down` під час дебагу зупинить і те,
  що поруч;
- **жодних портів** — у compose немає секції `ports`, конфліктів не буде;
- **ліміти** `mem_limit: 256m`, `cpus: 0.5` — сплеск активності не зачепить інші
  контейнери;
- **ротація логів** `max-size: 10m`, `max-file: 3` — найчастіша причина, чому
  маленький сервіс кладе великий сервер, це забитий логами диск, а не CPU;
- **власні креденшели** — свій токен, свій `.env` з правами 600, нічого
  спільного з іншими сервісами.

Перевірка після першого старту:

```bash
docker compose ls                  # ваш проєкт присутній окремим рядком
docker network ls                  # окрема default-мережа
ss -tulpn                          # список портів не змінився
docker stats --no-stream           # контейнер тримається в межах 256 MiB
```

Тест незалежності: зупиніть стек бота (`docker compose down`) і переконайтесь,
що решта сервісів живі; потім перезапустіть сусідній стек і переконайтесь, що
бот не постраждав.

## Моніторинг

- `HEALTHCHECK_URL` у `.env` — чек на [healthchecks.io](https://healthchecks.io)
  (період 10 хв, grace 10 хв). Бот пінгує його кожні 5 хвилин і лише тоді, коли
  зʼєднання з Telegram справді живе. Пінги зникли — прийде лист.
  Заводьте окремий чек: сторож не повинен ділити компоненти з тим, що стереже.
- `docker ps` показує healthy/unhealthy за heartbeat-файлом усередині контейнера.
- `/health` у самому боті (лише для адміністратора): аптайм, розмір бази,
  кількість користувачів і команд, недоставлені пари.

## Бекапи

Щодня о 03:00 (Київ) бот робить `VACUUM INTO data/backups/santa-YYYYMMDD.db`
і лишає останні 14 файлів. Вони всередині bind-mount, тож переживають
перезбірку контейнера. Копію можна забирати з сервера:

```bash
scp root@СЕРВЕР:/opt/santa-bot/data/backups/santa-$(date +%Y%m%d).db ~/Backups/
```

## Дані

`data/santa.db` містить персональні дані учасників (ПІБ, телефони, адреси
відділень). Тримайте директорію `data/` з обмеженими правами, не копіюйте
базу в загальнодоступні місця й памʼятайте про строки зберігання, описані
в `/help` самого бота.
